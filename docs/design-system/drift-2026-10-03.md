Not a new export. A re-read of one decision against the current file, at the
project owner's request: the SPA's Requests Queue drew a *Low stock alerts*
summary card the queue screen itself does not draw.

**Checked against**: `~/Downloads/Office Supplies Request System (OSRS).fig`,
the **2026-10-01** export ([drift-2026-10-01](drift-2026-10-01.md); 17,201 node

named `Label` inside a `Summary card`, with its page and top-level frame.

**Status: no constitution amendment needed.** Spec 004 FR-004 / FR-007 and

## 2. The decision

The file disagrees with itself. The queue screen — the frame `/queue` renders,
its sort-menu state and the prototype — draws **two** cards. Only the review
frames, which repeat the queue behind an open panel, draw a third, and so does
the retired Archive copy.

Spec 004 (Clarifications, 2026-09-24) resolved the split the other way: *"Keep
three."* That followed the review frames. It is **reversed**: the queue frame is
the screen, and the review frames are the queue under a panel, so where they
differ the queue frame wins. The card also had nothing to show — the API
publishes no low-stock count (contract conflict 15), so it read `—` everywhere.

- `/queue` draws **Pending approval** and **In Processing** only, two 262px
  cards ([spec 004 FR-004](../../specs/004-approver-pending-queue/spec.md)).
- Low stock stays visible where stock is managed: the `Low stock` chip on
  Assets and the stock pill on View Asset and the Catalog (spec 014, spec 005).
