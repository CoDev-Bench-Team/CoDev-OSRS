## How to read the file yourself

A `.fig` is a zip. Inside, `canvas.fig` is Figma's kiwi binary: an 8-byte
`fig-kiwi` magic, a version, then length-prefixed blocks — block 0 the compiled
kiwi schema (raw deflate), block 1 the document (**zstd** in this export;
older ones use deflate). `npm i kiwi-schema`, then
`compileSchema(decodeBinarySchema(block0)).decodeMessage(block1)` gives the
whole node tree, including `editInfo.lastEditedAt` per node. Embedded images sit
in `images/`, named by the SHA-1 that `fillPaints[].image.hash` carries.

### 1a. Correction to the first pass, 2026-09-15 (later)

The first reconciliation read the login pill out of the vendored
`ui_kits/osrs-web/LoginScreen.jsx`, which renders the instance as `0 6px` on
both plates, centred, with a 2px gap and the hairline as an inset shadow. That
is the *exporter's* re-render, and it disagrees with the file.

Figma's own computed layout for the instance is on the instance node, as
`derivedSymbolData`, and it resolves to:

| Part | Box | Origin |
|------|-----|--------|
| root (15:381) | 242×64, radius 32, white, **no visible stroke** (see below), padding-right 32, FIXED | the node's own properties |
| icon plate | 50×64 at (0,0), **fill `visible: false`**, padding `16 0 16 18` | `derivedSymbolData` + `symbolOverrides` |
| mark | 32×32 at (18,16) | `derivedSymbolData` |
| label plate | 173×57 at (50,3.5), padding `18 8 18 8` | `derivedSymbolData` + `symbolOverrides` |
| label text | at (8,18) inside that plate | `derivedSymbolData` |

So the content is packed left, not centred, and the root's 32px trailing pad is
what is left over of the fixed 242 — the plates sum to 223 and the file simply
lets them overflow the padded box.

**The pill has no border.** The root carries a 1px INSIDE stroke on all four
sides, and `strokePaints` caches `#000000` — but `styleIdForStrokeFill` binds it
to the `Surface` paint style, `#ffffff`, which paints white on a white fill.

The cache is not the authority. 70 of the file's 823 local style bindings
disagree with the style they point at, all of them in the same direction: a
style was retuned and the node kept the old value. The clearest family is the
brand red — `Codev Red` is now `#cc2f4a`, and a dozen nodes bound to it still
cache the retired `#c62828`, which the port already resolves the style's way as
`--color-osrs-red-500`.

The 2026-09-12 export read the cache and emitted
`inset 0 0 0 1px var(--border-strong)`; the first reconciliation followed it,
and so did the second. Reported by the project owner, 2026-09-15. Flagged to the
designer in [additions.md](additions.md) §"The sign-in card, composed in flow",
because a white borderless control on a white card no longer reads as a button —
if the `Surface` binding was a slip, the fix is one line.

The hidden plate fill is the part that matters structurally. The stroke is drawn
inside the root, so an opaque plate covers the top and bottom of it for the
plate's first 50px; that is why the first pass concluded the ring could not live
on the button and wrapped the control in a 1px-padded span. The wrapper cost two
pixels on both axes — 240×62 against the drawn 242×64. With the plate fill off,
as the file has it, the ring goes back on the button and the box is the drawn one.

The card is drawn at (510, 262) in the 1440×1024 frame and now renders there.
The seeded account chooser moved to the corner so that an affordance the design
does not contain cannot push the card off its drawn position.

## 2. Implemented — the top bar (spec 003 amendment, Session 2026-09-15)

The `Top Navigation` component now has two variants, both edited 2026-09-14:

| Variant | Navigation | Account cluster |
|---------|-----------|-----------------|
| Employee | Catalog · My Requests | Request List + count · **bell** · divider · avatar, name, role |
| Admin | Requests Queue · **History** · Inventory | **bell + count badge** · divider · avatar, name, role |

Three differences from what the shell shipped, all three now built:

1. **A notification bell**, in both variants, with a count badge on Admin. Built
   as a **marker, not a control** (FR-014a): the file draws no panel, list or
   destination for it, so it announces a count and opens nothing. Its glyph was
   extracted from the file, since the design system ships no bell. Its count
   comes from the same context the request-list badge uses.
2. **Profile is not a navigation item.** The `05 - Profile` screen uses the
   Employee bar with nothing marked current. Profile left the navigation sets
   (FR-006) and the **account cluster became the way in** (FR-006a) — the
   conventional place, and the only element on the bar about the signed-in
   person. The affordance is ours; the file draws none.
3. **History is a destination.** Added at `/history` for Approver and Supply
   Admin — the screen lists resolved requests across all requestors, so it is
   not an Employee's (theirs is My Requests).

Catalog was **kept** for the admin roles, which the drawn bar omits: the
authorization matrix gives every role the catalog, and that bar merges two roles
the constitution keeps apart, so it was already being overridden.

Unchanged and still true: the merged "Admin" identity the file draws is what
constitution II forbids and spec 003 D1 already overrides. The split stands.

Both were decided by the project owner and built:

- **`Cancelled` is a seventh status**, so the constitution moved to **2.0.0**:
  principle IV redefined to admit it from `Pending Approval`, `Approved` and
  `For Release`; principle III extended to its stock restore; principle V to its
  email. The version bump is MAJOR because a principle was redefined. Spec 001
  carries FR-009a–c, FR-014 and FR-016a; `docs/process-flow.md` carries the
  swimlane, the inventory rule and the notification; `src/shared/ui/status.ts`
  types the state.

  Three things the file does not say, and the amendment settles:

  | Question | Resolution | Why |
  |---|---|---|
  | Who may cancel? | The owning Employee while `Pending Approval` (reason optional); a Supply Admin on `Approved` or `For Release` (reason **required**); never once `Released` | The file names those two actors, then says "a reason is required when the **Approver** cancels" — an Approver its own sentence does not list. The reason requirement is attached to whoever is not the requestor. **Flagged.** |
  | What happens to stock? | Restored, in the same transaction as the status change | Constitution III leaves no alternative: stock is deducted at submit, and cancelled items never leave the store |
  | Which email? | A sixth notification, "Request Cancelled" | Constitution V does not allow a defined transition without one. **The copy is invented** — the file defines the status but no email |

- **`Completed` changed colour** from green to purple, and `Cancelled` takes the
  file's slate. Tokens, tints and contrast are in additions.md §2c. The stated
  colour rule had to change with it, which is the part worth ratifying.

A cancel flow is drawn — `04.2 - My Requests - Cancel Request` and
`04.2 - My Requests - Cancelled` — but building it is a page feature, not shell
work: spec 003 FR-024 keeps status transitions out of the shell entirely. The
vocabulary is ready for whoever builds that screen.

## 7. The token layer has the same disagreement — and one of them is the brand red

Found while reviewing the sign-in pill. The stale-cache pattern is not confined
to nodes: the 2026-09-12 export resolved several tokens from cached paints too,
so `tokens/colors.css` disagrees with the styles it was generated from.

Counted across the file: **822 local style bindings, 753 agreeing with the style
they point at, 69 not.** The disagreements cluster:

| Style | The style's value | What nodes still cache | Our token |
|-------|-------------------|------------------------|-----------|
| `Codev Red` | **`#cc2f4a`** — 262 bindings agree | `#c62828` × 24 | `--brand-primary` is **`#c62828`**, and `#cc2f4a` is carried separately as `--brand-primary-alt` |
| `Border-Strong` | `#d8d7d2` | `#ffffff` ×1 | `--border-strong` exports as **black**, which is what `ring-ink` paints |
| `Border` | `#e7e6e2` | `#000000` ×3 | split into `--osrs-border` `#e3e6ec` and `--osrs-border-warm` `#e7e6e2` |
| `Surface` | `#ffffff` | `#000000` ×4 | the four sign-in pills in §1 |

**The brand red is the one that matters.** If `Codev Red` at `#cc2f4a` is the
current brand colour, then the product's "two reds" — `--brand-primary`
`#c62828` and `--brand-primary-alt` `#cc2f4a`, recorded in `Button` as a
deliberate pair — are one red before and after a retune, and every `#c62828` in
the product is the retired value. The evidence points that way: 262 bindings
carry the new value against 24 holding the old, and the newest bar variant in
the file (Admin, edited 09-14) paints its current nav item `#cc2f4a` while the
Employee variant beside it still paints `#c62828`.

**Not changed here.** Repainting every red in the product on the strength of a
cache-versus-style reading is a designer's call, not a reviewer's, and it lands
squarely in the re-vendor below. Raised so that work starts from it rather than
rediscovering it.
